# P12 realized-run executable provenance mismatch

Supplied run_files.zip contains populated production-like run directories (e.g. 7876).

## Realized BBC

Example 7876.bbc:
  SWBOTB=2
  SW2=2
        DATE2     QBOT2
  31-dec-1970    0.0185    0.0188    0.0413
  ...

Thus each row contains three numeric values after DATE2.

## Supplied current source

hrulist2SWAP.f90 currently contains:
- commented three-value write: qq, flf, qlat;
- active write statement with qq only.

Therefore realized files were generated by an executable/source state whose BBC write behavior differs from the supplied current source.

The three realized columns are strongly consistent with the historical diagnostic order qq, flf, qlat, but this is not yet independently proven from executable metadata.

## Consequences

1. Do not claim byte-for-byte reproduction of the realized BBC from the current source.
2. Treat column 1 as the SWAP QBOT2 candidate because the header names QBOT2 and the historical source order places qq first; verify against exact-period heads before admission.
3. Preserve columns 2/3 as provenance/diagnostics; do not silently discard them in historical-compat fixtures.
4. Record source/executable identity in future P12 products.
5. The WBSEL01 semantic defect remains independent of this provenance mismatch.

## Missing input for direct first-row reproduction

The realized BBC starts at 31-dec-1970 for a 1971 run. Supplied modflow.zip currently contains 1970 paired head IDFs and only a layer-1 ASCII head for 1971-01-01. A paired layer-2 1971-01-01 head is required to directly reproduce the first realized qq row from heads+c1.
