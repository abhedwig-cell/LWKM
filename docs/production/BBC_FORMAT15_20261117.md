# BBC FORMAT15: precision-warning correction

## Scope

Only the final QBOT2 decimal token in `tools/server/bbc_production.py` changes from `.17g` to `.15g`. The calculation, signs, dates, spatial operations, physical cell areas, NPY checkpoints and full-precision transfer CSVs are unchanged. The report declares `BBC09_FORMAT15` and `bbc_float_format=.15g`. Nonfinite values are refused; small values are not clipped. Integer-valued reals retain a decimal point.

This is decimal rounding, not byte identity or a guarantee of bit-identical SWAP output. No model warnings are suppressed. MET07 and the two separate crop/irrigation defects are outside this correction.

## Source and actual evidence

Original LWKM source: commit `e9ef2495f2cf11028a457f7e13e4b6bc17ea20f6`, blob `a9ee5b4cfdc22114d551b623a3c3e2660e632df7`.

The public primary source `SWAP-model/ttutil`, commit `bd8601dca3cfb449a79accddd39a566811f1a75e`, `src/rdlex.for`, routine RDDECD, declares SIGDGM=15. It counts significand digits from the first nonzero through the mantissa and warns above 15. The exact identity of this public source with the server-linked TTUTIL build was not established. This is not a new source-authority decision about SWAP or LHM.

Actual received archive `SWAP_PROEF_TERUG.zip`, SHA256 `360cde505b6e0810450208b2c087bd79fac8d61994524039458e2b3ff9e84262`, contains `run_00001/1.bbc`, SHA256 `5abcecdf754317512d2b7c311837c809cca8c20a394feef2f95f9cce04b9928e`. All 19358 rows were checked. There are 19163 tokens above 15 significant digits, exactly matching the number of Many digits messages in the supplied swap.err. After formatting, zero tokens exceed 15. Maximum absolute decimal-text change: 5e-17 cm/day. Sum of absolute daily token changes: 3.63711111e-13 cm. These sums are input-text diagnostics, not a simulated water balance.

User example: `-0.026986001601585975` becomes `-0.026986001601586`, decimal difference -2.5e-17.

The retained fixture is the original header and first ten data lines, followed by an explicit end-of-table marker. The full historical input is not duplicated in Git.

## Tests actually performed

Twelve local unittest cases pass, including the user example, actual tokens, 10000 deterministic random values, tiny nonzero values, signed zero, nonfinite rejection, original producer execution with synthetic IDFs, unchanged transfer precision, resume and changed-identity rejection. The scientific SWAP model and exact server-linked parser were not invoked.

A separate original-versus-modified producer replay used three days, two sparse HRU IDs and five synthetic source roles. Mapping, population, all three NPY checkpoint files and all three transfer CSVs were byte-identical. The full HRU1 text-format replay was also performed. Detailed hashes and results are in the downloadable evidence JSON.

## Deployment boundary

No server file, executable, original hashed candidate directory or existing result was changed. This branch is not merged to main or the producer branch. The existing 82 successful results remain historical results for their original input bytes. This warning alone does not justify invalidating or rerunning them.

Do not run the modified original producer into an existing output directory: its code identity has changed, and the existing producer writes status and removes old manifests before refusing that changed identity. A fresh destination is required for any new producer run. Do not edit already catalogued BBC files in place.

For the current population the efficient next deployment is a versioned final-text conversion of existing BBC series, combined with the pending SWP/crop input revision and explicit new hashes/catalogues. This PR does not implement that migration and does not require rereading all MODFLOW rasters or recalculating meteorology. Actual SWAP acceptance of the new BBC representation remains a subsequent bounded model test. National start remains blocked by the independent crop defects.

Run only these tests from the repository root:

```cmd
python -m unittest discover -s tests -p test_bbc_numeric_format.py -v
```
